# 12 · 整理作品，写出有证据的复盘

陈一豪 / Ethan · AI 辅助编写 · 公开首版 · 预计 45 分钟

整理作品索引，挑一项讲清问题、修改、结果与局限。

**本课成果：** 一份作品索引、一张案例卡和下一轮改进任务。

材料为虚构教学示例；参考答案是预编写示范，不是模型实测。可以先手动练习，再在自己选择的 AI 工具中尝试。

## 先理解

### 作品可以小，状态必须准确

资料表、通知或纸面原型都能成为学习成果。设计、自测、别人试用和公开是不同状态。只记录实际完成的内容，缺课标未完成，不为凑齐作品补写经历。

### 留下判断，而不只留成品

案例卡保留原问题、输入、AI 参与、人的判断、修改证据和未决事项。发现资料矛盾并阻止错误发布，也是有价值的判断，不必包装成效率百分比。

### 整理与公开是两步

先整理工作包，再检查公开范围。成果可公开，不意味着含他人信息的原始输入也能公开。优先使用虚构材料；本课程不会替你发布或验证真实效果。

## 练习材料

### 虚构练习记录：只供学习写法

```text
P01 资料索引：完成三张纸面状态图，未编写程序。P02 资料问答：对三类题目手工核对来源，发现一条建议被误写成现行规则，修订后重新核对。P03 通知流程：完成正常与地点变更两轮纸面模拟，第二轮补上 v2 的确认记录。以上不是你的实际经历。
```

### 需要整理的范围

```text
从前面各课实际保存的任务单、通知、资料表、统计、计划、原型或流程中选择。没有自己的材料时，可以用 P01–P03 练习索引和写法，但整个工作包必须标注教学示例，不能写成个人实绩。
```

## 动手实践

### 1. 清点实际文件与状态

索引写作品名、问题、文件、状态、证据和待补事项。逐一打开文件，排除空文件与失效链接。先选三项说明学习过程的内容，其余列为待整理，不要求每课已有成品。

### 2. 写一张具体案例卡

选一项作品，按问题、材料、AI 工作、人的判断、实际观察、限制六段写。每句“已实现”“已检查”都找对应记录；如果只做了设计，保留设计状态。用 P02 演练时，应明确这是一段虚构案例，不能改成“我曾帮助共学站”。

### 3. 准备可展示的副本

源材料与展示稿分开放。展示稿去掉无关个人信息、内部备注及无依据的承诺，保留来源与示例标签。截图不等于功能验证，链接需实际打开。本课只整理候选副本。

### 4. 确定一项下一轮改进

挑一个小问题，写范围、预期与检查方法。例如把纸面原型做成本地页面，只验证搜索与清除。邀请别人阅读时记录实际反馈；没有反馈就写尚未邀请，不添加认可。

## 可复制的任务说明

```text
请仅根据我附上的真实练习记录或明确标注的教学示例，整理作品索引与一张六段案例卡。索引包含问题、文件、状态、检查证据和待补事项；案例卡包含问题、材料、AI 参与、人的判断、实际观察和限制。不要把设计写成已运行，把自测写成用户验证，把虚构案例写成我的经历。不要补编使用人数、效率收益或赞誉。最后提出一项能够单独验证的下一步改进，输出可审阅草稿，不代为发布。
```

## 判断练习

P01 只有三张纸面状态图，哪种作品介绍与证据相符？

- a：已上线资料平台，帮助多人提高检索效率。
- b：完成资料索引的三种状态设计，尚未实现程序。
- c：已完成可运行搜索，因为图里画出了搜索框。

## 参考与解释

判断题参考：b。纸面图支持设计完成这一结论，不能证明程序运行、上线或带来真实收益。清楚说明当前阶段，读者才能判断成果是什么。

```text
索引示例：P02｜区分规则与建议｜资料问答卡｜教学示例、手工核对三类题｜未开发程序。案例摘要：一条未批准建议被误写成规则；练习者重新核对来源，改回现行规则并保留建议状态。本次只检查给定三题，不代表所有问题都答对。这是依据 P02 记录的虚构写法示范，自己的案例须换成实际记录；下一步可增加一个无答案问题再检查。
```

## 成果自评

- [ ] 索引中的文件实际存在，作品状态与证据对应。
- [ ] 案例区分真实练习与教学示例，没有虚构他人反馈或收益。
- [ ] 展示副本清除无关信息，同时保留来源与重要限制。
- [ ] 下一轮只提出一项具体改进，并写出验收方式。

哪次判断最能体现你的学习？只看最终稿可能产生什么误解，应该补上哪条证据？
