# 09 · 把一个想法做成极小页面

陈一豪 / Ethan · AI 辅助编写 · 公开首版 · 预计 50 分钟

先用三条虚构资料设计一条能走通的查找路径，再按自己的条件选择纸面原型或本地网页。

**本课成果：** 一张页面需求卡、三个状态示例，以及标明实际检查范围的验收记录。

材料为虚构教学示例；参考答案是预编写示范，不是模型实测。可以先手动练习，再在自己选择的 AI 工具中尝试。

## 先理解

### 先完成一条路径

本课只做共学站资料索引：查看三条资料、按标题搜索、选择主题、清除条件。暂不加入登录、上传和在线问答。先画页面，再决定是否实现，目标是让输入产生可观察的结果。

### 页面要说明当前状态

页面要区分正常列表、无匹配和清除后恢复。没有匹配时明确说明，不显示空白页或编造资料。搜索和主题同时设置时，两种条件都满足才显示。

### 设计与运行分开记录

画出按钮只证明完成设计，实际点击得到结果才是运行检查。本课程页面不调用模型，也不会创建程序。可以只完成纸面路线，但须标注设计稿，不能称为已运行应用。

## 练习材料

### 虚构资料表

```text
A01：入门问答，主题为基础，说明是认识任务、材料与检查。A02：提问练习，主题为基础，说明是把模糊需求写清楚。A03：流程检查，主题为进阶，说明是检查状态与人工确认。三条均为虚构教学资料，本课不提供外部链接，不增加跳转按钮。
```

### 页面约定

```text
首次显示全部三条。搜索只匹配标题中的文字，忽略输入首尾空格；空搜索不限制标题。主题有全部、基础、进阶。清除操作同时清空搜索词并恢复全部主题。本版不新增资料，不保存用户输入，不接入模型。
```

## 动手实践

### 1. 写出谁要完成什么

用一句话描述：第一次来到共学站的人，能在三条资料中找到需要的主题。把四个操作和不做的功能抄进需求卡。不要把颜色、动画或智能推荐作为第一轮验收标准。

### 2. 画出三种状态

画初始页面、无结果页面、清除后的页面。无结果示例使用搜索词“问答”加进阶主题：两者没有共同匹配项。为每种状态写明可见条数和下一步动作，让别人无需听你解释也能照着操作。

### 3. 按条件选择实现方式

可以只完成纸面稿。已有开发环境时，可把下方任务交给 Codex 等工具，要求保存文件、打开预览并报告检查结果。本页只需虚构静态数据，不需输入密钥。操作方法可继续读《用好 Codex》。

### 4. 逐项核对并保存证据

检查默认列表、搜索“练习”、无结果组合、清除操作四项。纸面路线用状态图核对逻辑；网页路线实际操作并记录结果。失败时写下输入、预期和实际表现，只修改一个相关问题后再测。

## 可复制的任务说明

```text
请根据我附上的三条虚构资料和页面约定，完成一个极小资料索引。先复述范围，再列正常、无结果、清除后三种状态。若当前环境支持开发，保存可运行文件并启动本地预览，检查搜索与主题同时生效；否则交付明确标注的纸面设计，不声称程序已运行。不得加入登录、外部跳转、数据保存或模型调用。验收时区分预期结果与实际观察，并列出未验证项。
```

## 判断练习

搜索“问答”并选择进阶主题后没有记录，页面应该怎样处理？

- a：显示 A01，因为标题匹配比主题更重要。
- b：说明没有匹配结果，并提供清除条件的入口。
- c：自动生成一条进阶问答资料，让页面有内容。

## 参考与解释

判断题参考：b。本课约定标题和主题同时满足。A01 的主题为基础，不能显示；资料表之外的记录也不能自行添加。无结果是一种需要设计的正常状态。

```text
预期检查表：初始显示 A01、A02、A03；搜索“练习”且主题全部，仅显示 A02；搜索“问答”且主题进阶，显示零条与清除入口；清除后恢复三条、空搜索和全部主题。这是预期，不是运行证明。纸面作品注明“逻辑已核对，未实现程序”；网页作品另填实际结果与预览证据。
```

## 成果自评

- [ ] 需求卡包含使用者、四项操作及不做的功能。
- [ ] 三种页面状态的条数与参考规则一致。
- [ ] 四个检查场景分别记录预期与实际，未操作的项目写未验证。
- [ ] 成果准确标注为纸面原型或实际检查过的本地网页。
