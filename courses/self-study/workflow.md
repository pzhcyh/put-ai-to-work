# 11 · 用状态卡演练一个小工作流

陈一豪 / Ethan · AI 辅助编写 · 公开首版 · 预计 45 分钟

不接任何系统，用纸张或表格模拟从材料到通知的流转，找到必须停下等人的地方。

**本课成果：** 一张任务状态表、两条模拟执行记录，以及版本改变后的重新确认规则。

材料为虚构教学示例；参考答案是预编写示范，不是模型实测。可以先手动练习，再在自己选择的 AI 工具中尝试。

## 先理解

### 每一步都有输入与输出

“自动完成通知”太大。本课拆成整理材料、生成草稿、人工复核、模拟交付。整理输出事实表，生成输出带版本的草稿，复核输出批准记录或退回原因。下一步只能使用上一环节已经交付的内容，不能靠猜测补齐。

### 状态说明能否继续

使用待资料、待复核、已确认、已模拟交付四种状态。写完草稿不等于审核通过。本课只人工移动卡片，不运行自动化，不发布消息。

### 批准只针对具体版本

审核人批准 v1 后，如果地点改了，v2 需要重新复核。不能沿用旧版本的批准记录。将任务编号、草稿版本、确认人和确认范围放在一起，能够让接手的人看清目前哪一份可以使用。

## 练习材料

### 任务 G01：虚构共学站交流通知

```text
教学设定：10 月 12 日十五点至十六点进行资料整理交流，不收参与费，地点待确认。通知只供内部模拟，不真实对外发送。角色：小林整理资料，小周复核，小陈模拟交付；这些名字均为虚构。
```

### 稍后补充的确认卡

```text
小周确认地点为共学站一层阅览区。资料齐全后可形成草稿 v1。再次演练时，假设 v1 已确认，但小周随后把地点改为二层讨论区，此时生成 v2；原批准只针对 v1。
```

## 动手实践

### 1. 先摆出状态与交接物

在纸上写四个状态框，用 G01 卡片表示任务。卡片写资料版本、草稿版本、当前负责人及阻塞原因。初始地点缺失，停在待资料，下一步是请求小周确认地点，不是让 AI 选择一层或二层。

### 2. 走一遍正常流程

读入补充确认卡，整理事实表并写草稿 v1，移到待复核。扮演小周核对日期、时段、地点和费用，写下明确针对 v1 的确认记录后移到已确认。最后在模拟交付栏登记 G01/v1，再移到已模拟交付；不发送任何消息。

### 3. 演练版本变化

复制一份新的模拟记录，走到 v1 已确认时暂停，应用地点变更，生成 v2。把状态退回待复核，标注旧批准不适用。只有新的确认记录对应 v2，才能登记 G01/v2 的模拟交付。不要修改第一轮记录来掩盖变化。

### 4. 检查交接能否被复述

只读卡片，回答当前步骤、缺项、责任人和获准版本。重复模拟交付前，先查编号与版本，已有记录就不重复登记。这是纸面规则，不证明实际软件有防重复能力。

## 可复制的任务说明

```text
请把我提供的 G01 材料整理成可手动模拟的通知工作流。只使用待资料、待复核、已确认、已模拟交付四种状态。逐步列出输入、输出、负责人、允许前进的条件和退回原因；地点缺失时等待确认，草稿变化后撤销旧版本放行资格。提供正常路径与 v1 获准后改地点的异常路径。所有交付均为纸面登记，不发送消息、不接系统、不宣称已经自动执行。
```

## 判断练习

v1 已获确认，地点变化产生 v2，接下来应当怎样做？

- a：直接交付 v2，因为通知任务已经获准。
- b：保留已确认状态，只把文件名换成 v2。
- c：退回待复核，取得针对 v2 的新确认后再模拟交付。

## 参考与解释

判断题参考：c。旧确认针对 v1 的具体内容。地点属于读者会据此行动的事实，修改后必须重新核对，不能把批准任务误当作批准所有后续版本。

```text
正常示例：G01 待资料（缺地点）→补充一层阅览区并生成 v1→待复核→小周核对四项并确认 v1→已确认→登记 G01/v1 模拟交付→已模拟交付。变更示例：G01/v1 已确认→地点改为二层讨论区并生成 v2→待复核，旧批准失效→小周确认 v2→登记 G01/v2。登记表已有相同编号和版本时，停止重复登记，先检查是否只是重复操作。两条轨迹只是示范，实际练习须另写自己的操作记录。
```

## 成果自评

- [ ] 四种状态各有清楚含义和允许前进的条件。
- [ ] 每个交接写出输入、输出、责任角色与版本。
- [ ] 两轮记录分别保留，地点变化后确实重新复核。
- [ ] 模拟交付先查编号与版本，全程没有实际外发。

流程中哪一步最容易被一句“完成了”含糊带过？如果让另一位同事接手，卡片还缺少什么证据？
