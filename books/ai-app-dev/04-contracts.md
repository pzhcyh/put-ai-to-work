## 看得懂的文本，也需要机器边界

聊天界面让人以为输入输出只是两段文字。应用却需要据此决定是否调用服务、如何显示来源、怎样记录用量。缺少明确的数据约定，错误往往会在多个模块之间流动，到界面才表现成一个难以解释的空白。

我们把请求定义为一个对象，必须包含 `question`，可以包含 `k`。问题需要是去掉首尾空白后长度在1到400之间的字符串；`k` 是1到3之间的整数，默认2，表示最多取多少条匹配资料。不接受额外字段。这样的严格约定适合本书的小例子，也让“用户偷偷提交角色字段”的尝试有明确结果。

真实产品是否拒绝所有未知字段，可以根据兼容需求决定。但无论选择严格还是宽松，都应该明确记录，避免前后端各自猜测。输入长度限制也不是普遍最优值，400只是这次教学范围内可检查的上限。

## 从 JSON 解析到业务校验

JSON 能被解析，只能证明它符合一种数据表达方式，并不证明内容符合业务。`{"question":12}` 是合法 JSON，却不是合法问题。`{"question":"借阅","k":true}` 也能解析，但布尔值不应该在这个接口里表示检索条数。

样例使用 `type(k) is int`，刻意避免把布尔值接受为整数。问题长度用 Python 字符串长度计算，属于代码点计数，不应宣传为对所有语言都完全符合用户感知的“字数”。请求还设置4096字节的上限，先限制体积再解析。Python 官方文档也提醒，对不可信 JSON 输入应注意解析资源消耗并限制大小。[JSON 文档](https://docs.python.org/3/library/json.html)

真实网络服务还应在接收请求体时限制读取量。本书函数接到的字符串已经在内存里，所以这里的检查只是函数边界，不能替代反向代理或服务器的请求大小控制。把某一层检查的能力说清楚，才能避免误把局部措施当作全局保证。

## 输出约定让界面有稳定依据

成功响应包含四个字段：状态、回答、引用和模式。示例的成功状态必须是 `answered`，回答是长度受限的非空字符串，引用是无重复的字符串列表，且每个编号都属于本次允许进入生成环节的资料。

如果适配器返回 `not-found` 这个并不存在的引用，输出检查就会拒绝。这样可以阻止“看起来像来源”的编号直接进入界面。但它依然不能证明引用支持回答中的每句话。例如回答“借阅期限是三十天”，却引用了写着十四天的真实资料，编号检查仍不足以识别事实错误。接下来还需要内容评估或更严格的业务规则。

本书模拟器直接连接原句，减少了例子中的生成变量。换成真实模型之后，要单独设计回答与来源的一致性检查，不能把模拟场景的确定性想当然地继承过去。

## 错误是正常接口的一部分

我们给输入过长、JSON 错误、问题不合法、检索条数不合法、输出结构错误、引用错误和服务不可用分别定义错误码。页面可以把机器可识别的错误码翻译成合适的文字，而不必解析一段随时可能改写的中文错误消息。

| 错误码 | 用户能采取的动作 |
| --- | --- |
| `invalid_question` | 输入有效问题，或缩短问题 |
| `invalid_k` | 普通用户通常无需看见；开发者修正请求 |
| `service_unavailable` | 保留问题，稍后重试 |
| `invalid_citations` | 不展示这次不合格回答，转人工排查 |

服务端还可以返回一个请求编号，帮助定位同一次失败。请求编号不应该包含用户姓名、手机号或问题全文。用户提示和内部诊断需要不同详细程度；把原始错误对象直接发送到浏览器，可能暴露本不需要公开的信息。

## 结构约定会变化，所以给变化留记录

第一版只返回来源编号，下一版可能增加资料标题、版本和可访问链接。这时要先检查旧页面怎样处理新增字段，再决定是否升级接口版本。不要在未通知调用者的情况下，把 `citations` 从字符串列表换成对象列表。

可以把接口样例和测试一起保存在仓库中。一个正常请求、一个资料不足响应、几个典型错误，比一份很长却没有具体样例的说明更容易被共同理解。每次修改约定时，先更新期望行为，再修改实现和调用方。变更记录应该解释为什么改变，以及使用者需要做什么。

另一个常见失败是信任前端校验。前端限制输入长度能改善体验，但调用者可以绕过页面直接发送请求。业务边界仍然需要在服务端执行。两层校验目的不同，可以共享规则，却不应互相替代。

## 轮到你试一试

为你的应用写出正常请求、缺失问题、空白问题、错误类型、超长问题和未知字段六类样例。逐项记录预期结果，并确认实现真的拒绝不符合约定的输入。

再设计一个“格式正确、内容错误”的响应，说明现有校验为什么抓不到它。这个练习会帮助你分开两件事：接口需要结构可靠，回答需要证据可靠。交付物是一组可运行样例和一份未被结构校验覆盖的风险清单。
